## 3. 機能詳細

### FR-01 問い合わせ登録

「未対応」リストの下部に配置された登録ボタンから、新しい問い合わせを作成できること。新しい問い合わせは必ず未対応から始まるため、「対応中」「完了」リストには登録の操作を置かない（決定事項 No.10）。

登録時に入力・選択する項目は次のとおりとする。

| 項目 | 必須 | 初期値 | 備考 |
| --- | --- | --- | --- |
| 件名 | ○ | 空 | |
| 問い合わせ者 | ○ | 空 | |
| 問い合わせ内容 | ○ | 空 | 複数行 |
| 種別 | ○ | 質問 | 質問 / 不具合 / 要望 / その他 から選ぶ |
| 優先度 | ○ | 中 | 高 / 中 / 低 から選ぶ |

- 件名・問い合わせ者・問い合わせ内容のいずれかが空のとき（空白だけの入力を含む）は登録を行わない。その場合は、空の項目がどれかを利用者に分かるように示し、最初の空の項目に入力位置を移す（決定事項 No.11）。
- 入力値の前後の空白は取り除いてから保存する。
- 受付日には登録した日付を自動で設定する。利用者は受付日を入力・変更できない（決定事項 No.14）。
- 連絡先・対応者・対応期限・対応メモは登録時点では未設定とし、登録後に問い合わせ詳細で設定する（決定事項 No.13）。対応者は未割当の状態で登録される。
- 登録が終わったら入力欄を空に戻し、続けて次の問い合わせを登録できるようにする。

問い合わせを登録した後は、「未対応」リスト内を「3.1 優先度順の並べ替え規則」に従って並べ直すこと。登録時点の問い合わせには対応期限が無いため、新しい問い合わせは同じ優先度の問い合わせの末尾に表示される。

### FR-02 問い合わせ編集

登録済みの問い合わせについて、次の項目を問い合わせ詳細で変更できること。変更内容は即座に画面へ反映され、保存されること。

| 項目 | 空にできるか | 備考 |
| --- | --- | --- |
| 件名 | できない | |
| 問い合わせ者 | できない | |
| 連絡先 | できる | メールアドレスまたは電話番号。形式は検査しない |
| 種別 | できない（必ずいずれかを選ぶ） | |
| 問い合わせ内容 | できない | 複数行 |
| 対応メモ | できる | 複数行。回答した内容や対応の経過を記録する |

- 必須項目（件名・問い合わせ者・問い合わせ内容）を空にした場合（空白だけの入力を含む）は、その内容を保存しない。保存済みの内容は変更前のまま残る（決定事項 No.11）。
- 対応者（FR-06）・対応期限（FR-07）・優先度（FR-08）・ステータス（FR-04）も問い合わせ詳細で変更できる。それぞれの規則は各機能に定める。
- 受付日は表示のみとし、変更できない。

### FR-03 問い合わせ削除

登録済みの問い合わせを削除できること。削除の操作を行うと確認ダイアログを表示し、利用者が承諾したときだけ削除する。取り消した場合は何も変更しない（決定事項 No.4）。

確認ダイアログには、削除しようとしている問い合わせの件名と、削除は取り消せないことを示す。削除した問い合わせを元に戻す手段は本バージョンでは提供しない。

### FR-04 ステータス変更

問い合わせのステータスは、所属するリスト（未対応 / 対応中 / 完了）で表す。次のどちらの方法でもステータスを変えられること。

1. **ドラッグ&ドロップ**：問い合わせをマウスでドラッグし、別のリスト上でドロップする。ドラッグ中は、問い合わせが移動先のどこに挿入されるかを視覚的に示すこと。ドロップした位置に挿入する。
2. **問い合わせ詳細**：問い合わせ詳細でステータスを選ぶ。変更した問い合わせは、変更先のリストの末尾に置く（決定事項 No.18）。

ステータスの移り方に制限は設けない（「完了」から「対応中」や「未対応」へ戻すこともできる）。いずれの方法でも、移動結果は保存され、再訪時にも維持されること。ステータスの変更では優先度順の自動並べ替え（3.1）は行わない。

### FR-05 問い合わせの並べ替え

同一リスト内で問い合わせを上下にドラッグし、表示順を入れ替えられること。ドラッグによる並べ替えは優先度に関係なく自由に行えるものとし、並べ替えた順序は保存されること。

ドラッグによる並べ替えとは別に、問い合わせの登録（FR-01）および優先度の変更（FR-08）を行ったときは、システムがそのリスト内を優先度順に並べ直す。また、利用者が全リストの優先度順並べ替え（FR-10）を行ったときは、すべてのリストを並べ直す。規則は「3.1 優先度順の並べ替え規則」に定める。ステータスの変更（FR-04）では自動の並べ替えは行わない。

### FR-06 対応者の設定

問い合わせごとに、対応するメンバーの名前を 1 人分設定できること（決定事項 No.12）。

- 入力は自由入力とする。メンバーの一覧から選ぶ方式にはしない（メンバーの登録機能は本バージョンの対象外。要件定義書 4.2）。
- 入力値の前後の空白は取り除いてから保存する。空にした場合は未割当とする。
- カード表面に対応者を表示する。未割当のときは「未割当」と表示し、通常の表示と見分けられるよう赤字で目立たせる。
- 対応者の設定・変更では、問い合わせの位置は変えない。

### FR-07 対応期限の設定

問い合わせごとに、対応を完了すべき日付を 1 つ設定できること。任意項目とし、設定後に解除（未設定に戻す）こともできる。

設定された対応期限はカード表面に表示すること。対応期限を過ぎている問い合わせは、他と区別できる表示とする。ただし「完了」リストにある問い合わせは対応が終わっているため、期限を過ぎていても区別の表示は行わない（決定事項 No.3）。期限を過ぎたかどうかの判定基準（当日を含むか、どの時点の日付で判定するか）は基本設計で定める。

### FR-08 優先度の設定

問い合わせごとに「高 / 中 / 低」の 3 段階から優先度を 1 つ設定できること。優先度はカード表面に色付きの表示で示し、一覧を見た際に区別できるようにすること。

問い合わせ詳細で優先度を変更したときは、その問い合わせが属するリスト内を「3.1 優先度順の並べ替え規則」に従って並べ直すこと。変更した問い合わせは、変更後の優先度のまとまりの中で、対応期限に応じた位置に置かれる。

### FR-09 データ保存

登録・編集・ステータス変更・並べ替え・削除のすべての操作結果を、操作の都度バックエンド経由でデータベースに保存すること。アプリを開いた際には、データベースから最新の状態を取得して表示すること。これにより、別の端末やほかのメンバーがアクセスした場合でも同じ状態が表示されること。

チームの複数のメンバーが同時に利用することに伴い、次のとおりとする（決定事項 No.17）。

- ほかのメンバーの操作は、画面を開き直す（再読み込みする）と反映される。自動で画面に反映する仕組み（リアルタイムの同期）は設けない。
- 同じ問い合わせを複数のメンバーが同時に編集した場合は、後から保存した内容で上書きする。上書きの前に警告はしない。
- ほかのメンバーが削除した問い合わせを操作した場合（編集・移動・削除など）は、操作が保存できなかったことを利用者に通知する。
- あるメンバーの操作が、そのメンバーが操作していない問い合わせの内容を書き換えたり消したりしないこと（要件定義書 7.「同時利用」）。

サーバーと通信できない場合（ネットワーク未接続、サーバー停止など）は、操作が保存されていないことを利用者に分かるように通知すること。通知の方法や再試行の仕組みは基本設計で定める。

データが 3 つの層の間をどう流れるかは、[データ要件書](data-requirements.md)（作成予定）の「データフロー図」を参照すること。

### FR-10 全リストの優先度順並べ替え

ボード画面に、すべてのリストの問い合わせを優先度順に並べ直す操作を 1 つ配置すること。この操作はリストごとではなく全リスト共通であるため、各リストの枠の中ではなく、リストの外（ヘッダーとリストの間）に置く。

操作すると、「未対応」「対応中」「完了」の 3 つのリストそれぞれの中で、問い合わせを「3.1 優先度順の並べ替え規則」に従って高→中→低の順に並べ直し、結果を保存すること。同じ優先度の問い合わせどうしは、対応期限の近い順に並べる。優先度も対応期限も同じ問い合わせどうしの順序は変えない（ドラッグで整えた順序は、そのまとまりの中では保たれる）。

操作前の確認は求めない。並べ直す前の順序に戻す手段は提供しないが、ドラッグ（FR-05）で任意の順序に整え直せる（決定事項 No.16）。

### 3.1 優先度順の並べ替え規則

FR-01（問い合わせ登録）・FR-08（優先度の変更）の後にシステムが自動で行う並べ替えと、FR-10（全リストの優先度順並べ替え）で利用者の操作により行う並べ替えの規則を以下に定める（決定事項 No.15・No.16）。

- 並べ替えの対象は、FR-01 では「未対応」リストのみ、FR-08 では優先度を変更した問い合わせが属するリストのみとし、他のリストの順序は変更しない。FR-10 では 3 つのリストすべてを対象とする。
- リスト内の問い合わせを、優先度が「高」→「中」→「低」の順になるよう並べる。
- 同じ優先度の問い合わせどうしは、対応期限が近いものほど上に並べる（対応期限の日付が早い順）。期限を過ぎた問い合わせは日付が早いため、期限内のものより上になる。
- 対応期限が未設定の問い合わせは、同じ優先度の中で、対応期限が設定された問い合わせより下に置く。
- 優先度も対応期限も同じ問い合わせどうし（どちらも対応期限が未設定の場合を含む）は、並べ替え前の順序（ドラッグで整えた順序を含む）を維持する。
- FR-01・FR-08 では、操作した問い合わせ（登録した問い合わせ、または優先度を変更した問い合わせ）を、優先度も対応期限も同じ問い合わせの末尾に置く。FR-10 には「操作した問い合わせ」が無いため、この扱いは適用しない。
- 並べ替え後の順序は保存され、再訪時にも維持される（FR-09）。
- 対応期限の設定・変更（FR-07）だけでは並べ替えは行わない。期限を変えた問い合わせの位置は、次にこの規則による並べ替えが行われるときに反映される。

並べ替えの例（同じリストの中）：

| 並べ替え後の順 | 優先度 | 対応期限 | 備考 |
| --- | --- | --- | --- |
| 1 | 高 | 10/30 | 期限切れ（今日が 10/31 の場合）。日付が早いため最上位 |
| 2 | 高 | 11/02 | |
| 3 | 高 | 未設定 | 対応期限が未設定のものは、同じ優先度の最後 |
| 4 | 中 | 11/01 | 優先度が「中」のものは、「高」の後 |
| 5 | 中 | 11/05 | |
| 6 | 低 | 11/01 | 対応期限が近くても、優先度が低いものは下 |

ドラッグによる並べ替え（FR-05）およびステータスの変更（FR-04）では、この規則による並べ替えは行わない。利用者がドラッグで整えた順序は、次にそのリストで問い合わせの登録または優先度の変更が行われるか、全リストの優先度順並べ替え（FR-10）が行われるまで維持される。
